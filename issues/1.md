## Overview
Redesign the Method editor (`BrewMethodEditor.tsx`) to use a step-based workflow instead of the current single-form approach. This will improve UX by breaking down the complex method creation process into manageable steps with clear navigation.

## Step-Based Workflow

### Step 1: Basic Information
- **Name** (required)
- **Description** (optional)
- **Category** (required)
  - Dropdown list of existing categories (e.g., "Pour over", "4:6 Method", "James Hoffmann", "Custom")
  - Allow typing to create a new category

### Step 2: Helper Values
- **Coffee Amount** (grams)
- **Water Ratio** (1:X)
- **Total Water** (auto-calculated: coffee × ratio)
- Users should be able to navigate back to edit these values at any time

### Step 3+: Brewing Steps (Iterative)
Each brewing step should capture:
- Water amount (grams)
- Pour time (seconds)
- Description (optional)

After adding/editing each brewing step, user can:
- **Add another brewing step** → Creates a new step in the wizard
- **Save and finish** → Completes the method creation

### Navigation
- **Back/Forward buttons** to navigate between all steps
- Ability to return to Step 1 or Step 2 from any brewing step
- Clear indication of current step and progress

### Progress Tracking
Display throughout the brewing steps:
- **Total water used** (cumulative across all steps)
- **Total time** (cumulative time of all steps + drawdown time)
- Update these values as user adds each brewing step

### Validation
- **Block progression** if required fields are not filled
- **Draft saving** as user moves between steps (autosave progress)
- **Maintain existing validation**: Total water percentage must equal 100%
  - Current validation: `Math.abs(totalPercentage - 100) > 0.01`
  - Show clear error message if total doesn't equal 100%
- Pour times must be in ascending order
- All percentages and times must be non-negative
- Drawdown time must be valid

### Editing Existing Methods
- When editing a method with multiple brewing steps, load all steps into the wizard
- Allow navigation through all existing steps
- Maintain ability to add new steps or modify existing ones

## Technical Notes
- Keep the same data structure (`BrewMethod` type)
- Maintain gram-based input with percentage calculation (current implementation)
- Preserve drawdown time functionality
- Follow the pattern of inline forms (not modals) as per project guidelines

## UI/UX Considerations
- Clear step indicators (e.g., "Step 1 of 3")
- Progress bar showing completion
- Disabled "Next" button when validation fails
- Visual feedback for cumulative totals
- Confirmation before discarding unsaved changes
